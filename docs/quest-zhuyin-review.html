Quest 注音鍵盤總審查

系統輸入法在 Quest 3S（Horizon OS 2.7）上真的能用：能啟用、能切換、能打整句。輸入體驗和選字已經是可日常試用的原型；專案已經進版本控制，但還沒有發布所需的簽章、授權聲明和使用者引導。

頭盔上實測確認的事

以下每一條都是在使用者的 Quest 3S 上用系統記錄或實際操作驗證過的，不是推論。

  • 裝置與系統Quest 3S，Horizon OS 2.7（版號 207，2026-08-26 建置），Android 14 / API 34。
  • 啟用輸入法系統會登記第三方輸入法；Meta 設定裡沒有開關，但指名開啟 Android 原生「螢幕鍵盤」頁可以打開。系統的輸入法選單可以叫出來，從鍵盤上也行。
  • 透明與模糊面板可以半透明；背景模糊不支援（未宣告模糊支援、系統模糊開關為關、要求的模糊半徑沒有生效）。
  • 穩定性多輪實際使用與監看（打字、逐段選字、表情、換配色與透明度、切換輸入法）都沒有當機或錯誤記錄。
  • 隱私只宣告麥克風權限，沒有網路權限，詞庫與選字完全在頭盔上離線運作。

風險與技術債

依影響排序，已解決的放在最後。「高」是現在就會造成損失或讓整個專案失效的事。

高

Meta 可能再次封鎖第三方輸入法（v77.1027 曾拿掉切換介面），而啟用流程依賴指名開啟原生設定頁。

保留「App 內打字再複製」的退路設計；每次 Horizon OS 更新都跑一次啟用與切換的回歸檢查。

中

發布前要處理授權：詞庫資料含 LGPL-2.1 以上（libchewing-data）與 LGPL-3.0（Rime Essay）。

App 內加授權聲明與來源連結，確認 LGPL 資料的散布方式符合條款。

中

整份詞庫以 JSON 解析進記憶體，Java 記憶體約 61 MB；輸入法行程被系統回收後，重新載入要花多久不知道。

先量測，再考慮改成預先建好的二進位索引。

中

鍵盤主類別 847 行，畫面、狀態、選單、表情、鍵帽繪製都在一起，改一處容易牽動別處。

拆成鍵帽繪製、按鍵區、候選列、選單、表情頁幾個部分。

低

麥克風權限已宣告，但語音輸入還沒實作。

語音做好前可以先拿掉，或在 App 內說明用途。

低

無線偵錯連線會因頭盔休眠中斷，拖慢開發測試。

開發時插 USB，或暫時關閉休眠偵測。

未來方向

階段有先後：前一階段是後一階段的地基，順序不建議對調。

第一階段：穩住地基

約 1–2 天目標：不會弄丟、離開 Claude 也能建置、數字看得見
  • 把專案 commit 進版本控制　已完成（9e402b9）；之後每個功能一個 commit。
  • Android SDK 搬出 Claude 的私人資料夾　已完成，重新編譯與測試通過。
  • 加上正式簽章與版本號設定。
  • 量測啟動時間、每按一鍵的延遲、記憶體，寫成可重跑的檢查。
  • 拆分鍵盤主類別。

第二階段：補齊選字引擎

約 1 週目標：跟 Windows 版的選字品質對齊
  • 移植個人詞庫與學習：記住使用者選過的字與上下文。
  • 移植錯字修正與近音修正（ㄣ／ㄥ、ㄓ／ㄗ 等）。
  • 詞庫改成預先建好的二進位索引，降低記憶體與啟動時間。
  • 用 Windows 版的測試案例批次比對兩邊的輸出。

第三階段：打磨體驗

約 1 週目標：新使用者不看說明也能用
  • 首次使用引導：三步驟帶使用者啟用、切換、試打。
  • 游標左右移動與句子中間修改。
  • 按鍵音效，並確認頭盔上的明體字型是否可用。
  • 表情膚色選擇、更多符號。

第四階段：離線語音輸入

約 1–2 週目標：講話直接出台灣正體中文，不上傳聲音
  • 評估 sherpa-onnx 的中文模型：大小、準確度、授權、頭盔上的速度。
  • 接上簡體轉台灣正體（OpenCC s2twp）。
  • 模型檔案下載前先向使用者確認來源與大小。

第五階段：發布

持續目標：讓其他 Quest 使用者裝得到、用得安心
  • App 內授權聲明與隱私說明（強調完全離線）。
  • 先上 SideQuest 收集回饋，再確認 Horizon Store 對輸入法類 App 的政策。
  • 建立 Horizon OS 更新回歸清單：780 × 355 面板、半透明、原生設定入口、輸入法選單。
  • 在 Quest 3 與其他機型上驗證。
